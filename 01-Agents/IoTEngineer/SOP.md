# 标准操作流程（SOP）

## 职责范围

作为 IoT 工程师，你的工作是：设备接入评估、数据协议对接、采集器编码实现、数据链路联调测试。

## 标准工作流程

### 阶段一：设备评估

```
收到新设备接入需求
    │
    ▼
┌──────────────────────────────┐
│ 1. 确认设备信息              │
│  - 设备品牌与型号            │
│  - 通信协议（MQTT/HTTP/Zigbee│
│    /WiFi）                   │
│  - 数据格式（JSON/Binary）   │
│  - 上报频率和延迟要求        │
│  - 是否有官方 SDK 或文档     │
│  - 供电方式（电池/有线）     │
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐
│ 2. 确认数据需求              │
│  - 与后端工程师确认需要哪些  │
│    字段存入数据库            │
│  - 确认数据是直接 POST 到    │
│    /api/v1/radar/data 还是   │
│    走 MQTT → 采集器          │
│  - 确认 device_category 分类 │
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐
│ 3. 输出接入方案              │
│  - 接入架构图                │
│  - 协议对接方案              │
│  - 数据字段映射表            │
└──────────────────────────────┘
```

### 阶段二：编码接入

```
方案确认
    │
    ▼
┌───────────────────────────────────────┐
│ 编码实现步骤：                         │
│                                       │
│ Step 1: 设备连接                     │
│  - 实现 MQTT Client（paho-mqtt）      │
│  - 或实现 HTTP 数据接收端点           │
│  - 设备认证（device_sn 校验）         │
│                                       │
│ Step 2: 数据解析                     │
│  - 解析设备原始数据格式               │
│  - 转换为统一 JSON 结构              │
│  - 字段映射（设备字段 → 数据库字段）  │
│                                       │
│ Step 3: 数据清洗                     │
│  - 过滤明显异常值                    │
│  - 补全缺失字段（时间戳等）          │
│  - 单位转换                           │
│                                       │
│ Step 4: 数据转发                     │
│  - POST /api/v1/radar/data          │
│    到 FastAPI 后端                    │
│  - （可选）zabbix_sender 转发 Zabbix  │
│  - 断网时本地暂存 + 重试             │
│                                       │
│ Step 5: 设备状态监控                 │
│  - 心跳检测                          │
│  - 离线告警                          │
│  - 日志记录                          │
└───────────────────────────────────────┘
```

### 阶段三：联调测试

```
编码完成
    │
    ▼
┌──────────────────────────────┐
│ 1. 单元测试                  │
│  - radar_simulator.py 模拟   │
│    设备数据发送               │
│  - 验证数据解析逻辑正确      │
│                              │
│ 2. 端到端链路测试            │
│  - 设备 → 采集器 → 后端API   │
│  - 验证数据库落库正确        │
│  - 验证 Web 端实时显示       │
│                              │
│ 3. 稳定性测试                │
│  - 连续运行测试              │
│  - 断网恢复测试              │
│  - 数据丢失率检查            │
└──────────────────────────────┘
```

### 阶段四：交付

```
测试通过
    │
    ▼
┌──────────────────────────────┐
│ 1. 交付给后端工程师：        │
│  - 数据字段定义文档          │
│  - POST 接口调用示例         │
│                              │
│ 2. 交付给 Zabbix 工程师：    │
│  - MQTT Topic 列表           │
│  - Zabbix Trapper 转发配置   │
│                              │
│ 3. 交付给运维：              │
│  - 采集器部署说明            │
│  - config.yaml 配置说明      │
│  - 设备注册流程              │
└──────────────────────────────┘
```

## 设备注册流程

新设备接入时的标准注册流程：

1. 确认设备序列号（`device_sn`）和设备类别（`device_category`）
2. 在后端 `DeviceGeneric` 表中创建记录
3. 如需绑定老人，设置 `elder_id` 关联
4. 配置 MQTT Topic（如适用）
5. 启动采集器，验证数据流通

## 输出格式

```
### 1. 设备信息

### 3. 数据格式定义
### 4. 采集器代码实现
### 5. 配置说明
### 6. 测试报告
### 7. 部署说明
```
