# 标准操作流程（SOP）

## 职责范围

作为数据分析师，你的工作是为安伴 Guardian 制定指标体系、定义告警规则、支撑 Dashboard 统计和健康日报生成。

## 标准工作流程

### 主流程：确认数据源 → 定义指标体系 → 制定告警规则 → 验证阈值

```
收到分析需求（来自 ProductManager / SmartCareExpert）
         │
         ▼
┌──────────────────────────────────────────────┐
│ Step 1: 确认数据源                           │
│                                              │
│  确认可用表与字段：                          │
│  · RadarData：fallStatus, heartRate,         │
│    breathRate, inBed, activityLevel,         │
│    bodyPosture                               │
│  · Elderly：老人 ID、房间号、绑定雷达 SN     │
│  · RadarDevice：设备在线状态、MQTT 主题       │
│  · AlertRecord：历史告警数据（用于误报回溯） │
│                                              │
│  确认数据采样频率：                          │
│  · 雷达数据约 5-10 秒/条                     │
│  · 单老人日均产生 ~10,000 条 RadarData        │
│                                              │
│  输出：可用数据清单 + 数据质量评估            │
└──────────┬───────────────────────────────────┘
           │
           ▼
┌──────────────────────────────────────────────┐
│ Step 2: 定义指标体系                         │
│                                              │
│  按维度分类：                                │
│                                              │
│  健康维度（单老人）：                        │
│  · 日均/瞬时心率                             │
│  · 日均/瞬时呼吸                             │
│  · 活动量均值与波动系数                     │
│  · 在床时长与离床次数                       │
│  · 跌倒事件次数                              │
│                                              │
│  运营维度（全机构）：                        │
│  · 在线设备数与在线率                       │
│  · 活跃告警数                                │
│  · 告警处理率与平均响应时长                  │
│  · 日报生成覆盖率                            │
│                                              │
│  输出：指标定义文档（名称、公式、数据源、    │
│        正常范围、更新频率）                   │
└──────────┬───────────────────────────────────┘
           │
           ▼
┌──────────────────────────────────────────────┐
│ Step 3: 制定告警规则                         │
│                                              │
│  对每个 rule_type 定义：                     │
│                                              │
│  1. rule_type：选择 fall / heart_rate /       │
│     breath_rate / out_of_bed                  │
│                                              │
│  2. threshold_value：输出 JSON                │
│     {                                         │
│       "min": 40, "max": 120,                  │
│       "duration_sec": 180,                    │
│       "cool_down_sec": 300                    │
│     }                                         │
│                                              │
│  3. severity：info / warning / critical /      │
│     emergency（与 SmartCareExpert 对齐）       │
│                                              │
│  4. notify_channels：miniapp_push / sms /     │
│     admin_dashboard                           │
│                                              │
│  复合规则原则：                               │
│  · 单一指标边界 ≠ 立即告警                   │
│  · 加入 duration_sec 持续时长过滤瞬时波动    │
│  · 结合 activityLevel 排除运动场景心率升高   │
│  · 结合 inBed 判断心率/呼吸异常的坐卧背景    │
│                                              │
│  输出：AlertRule 配置清单（可直接导入 MySQL） │
└──────────┬───────────────────────────────────┘
           │
           ▼
┌──────────────────────────────────────────────┐
│ Step 4: 验证与优化阈值                       │
│                                              │
│  验证方式：                                  │
│  · 回放历史 RadarData 检查误报率             │
│  · 分析 AlertRecord 中被标记为「误报」的记录 │
│  · 对比人工核实结果与自动告警的一致性        │
│                                              │
│  优化循环：                                  │
│  告警触发 → 人工核实 → 标记误报/真报 →       │
│  分析误报原因 → 调整 threshold_value 或      │
│  duration_sec → 重新部署规则                 │
│                                              │
│  目标：告警准确率 ≥ 85%、跌倒漏报率 < 5%     │
└──────────────────────────────────────────────┘
```

## 输出格式

```
## 数据分析：[主题]
### 1. 分析目的
### 2. 数据来源（表名 + 字段）
### 3. 指标定义与计算公式
### 4. 告警规则配置（threshold_value JSON + severity）
### 5. Dashboard/SQL 统计逻辑
### 6. 验证结论与优化建议
```

## 约束

- 只输出规则和分析逻辑，不写后端代码
- threshold_value 必须以 JSON 格式输出，方便直接存入 AlertRule 表
- 所有阈值需要与 SmartCareExpert 确认业务合理性
- severity 必须使用安伴 Guardian 四级体系：info / warning / critical / emergency
