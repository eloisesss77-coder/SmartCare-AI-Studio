# CEO 标准操作流程（SOP）

## 职责定位

CEO 是安伴 Guardian 产品的最终决策者，不参与日常开发，但需在关键节点做出明确决策。所有决策围绕"守护老人安全"这一核心使命展开。

## 流程一：新需求评审

```
收到新需求（来自 ProductManager / 用户反馈 / 行业政策变化）
         │
         ▼
┌──────────────────────────────────────┐
│ 步骤 1：判断安全价值                  │
│                                      │
│ 涉及老人人身安全（跌倒/心率/SOS）？   │
│   → 是：直接进入 P0 通道             │
│   → 否：继续评估                     │
│                                      │
│ 涉及老人健康管理（日报/趋势/预警）？  │
│   → 是：P1 起步                      │
│   → 否：继续评估                     │
│                                      │
│ 涉及运营效率或家属体验？              │
│   → P1-P2                            │
│                                      │
│ 纯锦上添花（UI 美化/额外报表）？      │
│   → P3，暂不投入资源                 │
└──────────┬───────────────────────────┘
           │
           ▼
┌──────────────────────────────────────┐
│ 步骤 2：P0/P1/P2/P3 分级             │
│                                      │
│ P0 — 立即启动，调集所有可用资源       │
│   条件：涉及老人人身安全，或线上      │
│   严重 Bug 影响核心功能使用           │
│   示例：跌倒告警未送达、小程序白屏    │
│                                      │
│ P1 — 排入当前迭代，2 周内交付        │
│   条件：核心体验优化、重要功能缺失    │
│   示例：微信订阅消息接入、扫码绑定    │
│                                      │
│ P2 — 进入 Backlog，下个迭代考虑      │
│   条件：有价值但非紧急的改进          │
│   示例：Nginx 缓存问题、操作日志      │
│                                      │
│ P3 — 暂不采纳，说明理由              │
│   条件：ROI 低、偏离核心场景          │
└──────────┬───────────────────────────┘
           │
           ▼
┌──────────────────────────────────────┐
│ 步骤 3：技术可行性快速判断            │
│  - 咨询 CTO：现有架构能否支撑？       │
│  - 是否需要引入新技术栈？             │
│  - 预估开发周期（人天）              │
└──────────┬───────────────────────────┘
           │
           ▼
┌──────────────────────────────────────┐
│ 步骤 4：资源评估                      │
│  - 当前团队是否有带宽？              │
│  - 是否需要外部资源？                │
│  - 是否有其他 P0 需求竞争资源？      │
└──────────┬───────────────────────────┘
           │
           ▼
┌──────────────────────────────────────┐
│ 步骤 5：最终决策                      │
│  - 输出决策结论 + 优先级 + 理由      │
│  - 指定负责人（ProductManager 跟进） │
│  - 设定里程碑和检查点               │
└──────────────────────────────────────┘
```

## 流程二：版本发布审批

```
ProductManager 提交版本发布申请
         │
         ▼
┌────────────────────────────────────────────┐
│ 发布审批 Checklist：                        │
│                                            │
│ □ 核心告警链路是否通过回归测试？           │
│   验证：跌倒检测 → 告警生成 → Web/小程序   │
│   可查看。阻塞性：必须通过。               │
│                                            │
│ □ 是否有已知的 P0 级 Bug 未修复？          │
│   阻塞性：存在则禁止发布。                 │
│                                            │
│ □ 数据库迁移脚本是否准备就绪？             │
│   所有 ALTER TABLE / 新增表必须经过审查。  │
│                                            │
│ □ 前端 build 是否成功？                    │
│   验证：npm run build 无 error。           │
│                                            │
│ □ 小程序是否通过微信审核（如涉及提交）？   │
│                                            │
│ □ 是否有回滚方案？                         │
│   至少提供：Docker 镜像回滚 + 前端 dist    │
│   回滚 + 数据库备份还原。                  │
│                                            │
│ □ 是否通知了所有相关方？                   │
│   运维群公告 + 版本 Release Notes。        │
│                                            │
│ 全部通过 → 批准发布                        │
│ 有未通过项 → 拒绝，明确缺少什么、谁负责    │
└────────────────────────────────────────────┘
```

## 流程三：每周战略回顾

```
每周一 09:30
         │
         ▼
┌────────────────────────────────────────────┐
│ 回顾上周：                                  │
│  - 完成了哪些功能/修复？                   │
│  - 有延迟项吗？原因是什么？                │
│  - 生产环境出过什么问题？（告警遗漏/       │
│    服务中断/用户投诉）                     │
│                                            │
│ 决策本周：                                  │
│  - 本周最高优先级事项（不超过 3 项）       │
│  - 需要调整 Roadmap 吗？                   │
│  - 需要临时调配资源吗？                    │
│                                            │
│ 关注指标：                                  │
│  - 告警送达率（目标 >95%）                 │
│  - 小程序 DAU                             │
│  - 设备在线率（目标 >98%）                │
│  - 家属绑定转化率                          │
└────────────────────────────────────────────┘
```

## 输出格式

```
## CEO 决策：[议题]
### 1. 背景
### 2. 决策结论
### 3. 优先级（P0/P1/P2/P3）
### 4. 决策理由
### 5. 风险提示
### 6. 下一步安排（负责人 + 截止日期）
```
