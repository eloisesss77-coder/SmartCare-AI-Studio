# 标准操作流程（SOP）

## 职责范围

作为后端工程师，你的工作是：设计 REST API、数据库建模、编写业务逻辑、集成第三方服务。

## 标准工作流程

### 阶段一：需求分析

```
收到需求
    │
    ▼
┌──────────────────────────────┐
│ 1. 理解需求                  │
│  - 涉及哪些数据实体？         │
│  - 需要哪些新 API？          │
│  - 需要哪些外部集成？        │
│  - 有哪些性能要求？          │
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐
│ 2. 确认 API 设计            │
│  - 路径规范：/api/v1/{模块}  │
│  - HTTP 方法：GET/POST/PUT   │
│  - 请求参数与响应格式        │
│  - 与前端对齐接口定义        │
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐
│ 3. 确认数据库变更            │
│  - 新增表还是修改现有表？     │
│  - 字段类型/索引/约束        │
│  - 是否影响现有数据迁移？    │
└──────────────────────────────┘
```

### 阶段二：接口设计

```
需求确认
    │
    ▼
┌───────────────────────────────────────┐
│ 接口设计输出：                         │
│                                       │
│ 1. API 路径与 HTTP 方法               │
│ 2. 请求 Schema（Pydantic BaseModel）  │
│    - 必填/可选字段                    │
│    - 类型校验                         │
│    - 自定义验证器                     │
│ 3. 响应 Schema（alias_generator）     │
│ 4. 认证方式标注                       │
│    - 管理端：Bearer Token             │
│    - 小程序：X-Family-Id              │
│    - 公开接口：无需认证               │
└───────────────────────────────────────┘
```

### 阶段三：代码实现

```
接口设计确认
    │
    ▼
┌─────────────────────────────┐
│ 代码实现顺序：               │
│                             │
│ 1. models.py — 数据模型    │
│    - 继承 Base              │
│    - __tablename__ = "t_xxx"│
│    - Column 定义 + comment  │
│                             │
│ 2. schemas.py — Pydantic   │
│    - 请求模型 (Create/Update│
│      /Query) 保持 snake_case│
│    - 响应模型 设置 alias    │
│      generator=to_camel     │
│                             │
│ 3. routers/xxx.py — 路由   │
│    - APIRouter(prefix, tags)│
│    - Depends 注入认证和 DB  │
│    - 统一返回 ApiResponse   │
│                             │
│ 4. services/xxx.py — 服务  │
│    - 核心业务逻辑           │
│    - 复杂查询/聚合          │
│    - 外部 API 调用          │
└─────────────────────────────┘
```

### 阶段四：路由注册

```
路由实现完成
    │
    ▼
┌─────────────────────────────┐
│ 在 main.py 中注册：         │
│                             │
│ app.include_router(         │
│   xxx.router                │
│ )                           │
│                             │
│ 每个模块有独立的 prefix:    │
│ - /api/v1/elderly          │
│ - /api/v1/radar            │
│ - /api/v1/alerts           │
│ - /api/v1/dashboard        │
│ - /api/v1/auth             │
│ - /api/v1/users            │
│ - /api/v1/family           │
│ - /api/v1/devices          │
└─────────────────────────────┘
```

### 阶段五：数据库变更

```
模型变更
    │
    ▼
┌─────────────────────────────┐
│ 开发环境：                  │
│ - Base.metadata.create_all  │
│   在 lifespan 中自动执行    │
│ - 重启服务即生效            │
│                             │
│ 生产环境（建议）：          │
│ - 使用 Alembic 迁移管理     │
│ - 手动执行 DDL 前先备份     │
│ - 索引变更需评估锁表风险    │
└─────────────────────────────┘
```

### 阶段六：提交前自查

```
代码完成
    │
    ▼
┌───────────────────────────────────────┐
│ 提交前 Checklist：                    │
│                                       │
│ □ 模型有完整 comment 注释             │
│ □ Schema 有 Field 校验和描述          │
│ □ 路由有 response_model 标注          │
│ □ 接口有认证依赖注入（需认证的）       │
│ □ 敏感操作有权限检查                  │
│ □ 数据库查询无 N+1 问题               │
│ □ 异常有统一处理（不抛原始异常）       │
│ □ 日志使用 logging.getLogger(__name__) │
│ □ 统一返回 ApiResponse 结构           │
│ □ Swagger 文档 /docs 可正常访问       │
│ □ uvicorn 启动无报错                  │
│                                       │
│ 全部通过 → 提交 Git                   │
└───────────────────────────────────────┘
```

## 输出格式

```
## 后端实现：[模块名称]
### 1. 功能描述
### 2. 数据库模型设计
### 3. API 接口定义（含请求/响应示例）
### 4. Router 实现代码
### 5. Service 实现代码
### 6. Schema 定义
### 7. 认证说明
```
