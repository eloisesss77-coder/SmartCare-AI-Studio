# Dify 工作流设计参考

> 本文件由 AIEngineer 维护。
> 
> ⚠️ **重要说明**：Dify 在 SmartCare AI Studio 中为**可选的 AI 增强层**。核心业务逻辑（告警判断、数据存储、日报生成、微信推送）均由 FastAPI 后端独立处理。Dify 工作流作为 AI 增强层，可提供智能化的护理建议生成和自然语言问答能力。

## 核心概念

| 概念 | 说明 |
|------|------|
| Workflow | 工作流，由多个节点组成的有向无环图 |
| Node（节点） | 工作流中的最小执行单元 |
| Variable（变量） | 节点间的数据传递载体 |
| Chatflow | 对话式工作流，支持多轮对话 |
| Knowledge（知识库） | RAG 检索增强生成的数据源 |

## 节点类型

| 类型 | 说明 | SmartCare 使用场景 |
|------|------|-------------------|
| **Start** | 工作流入口 | 接收 Zabbix Webhook 或 API 参数 |
| **End** | 工作流出口 | 返回 AI 分析结果 |
| **LLM** | 大语言模型调用 | 生成护理建议、日报 |
| **Code** | 代码执行（Python/JS） | 查询 Backend API、数据处理 |
| **Knowledge Retrieval** | 知识库检索 | 检索养老知识库内容 |
| **HTTP Request** | HTTP 接口调用 | 调用 Backend API |
| **IF/ELSE** | 条件分支 | 按告警等级分流处理 |
| **Template** | 模板转换 | 格式化推送消息 |
| **Variable Aggregator** | 变量聚合 | 合并多个分支的输出 |

## SmartCare 核心工作流模板

### Flow 1：告警处理（alert-processing）

```
Start（接收 Webhook 参数）
  │  elder_id, device_type, alert_level, trigger_name, value
  │
  ├─→ Code：查询老人档案（GET /api/v1/elder/{elder_id}）
  │
  ├─→ Code：查询历史告警（GET /api/v1/alert/history/{elder_id}）
  │
  ├─→ Knowledge Retrieval：检索相关护理知识
  │    查询："{trigger_name} 的护理处理建议"
  │
  ├─→ IF/ELSE：按告警等级分流
  │   ├── urgent → LLM：紧急通知（立即推送）
  │   ├── important → LLM：重要提醒（15分钟内）
  │   └── normal → LLM：日常关注（1小时内）
  │
  └─→ Code：推送通知（POST /api/v1/push/send）
      → End
```

### Flow 2：日报生成（daily-report）

```
Start（接收 elder_id）
  │
  ├─→ Code：获取今日数据（心率、活动、睡眠、如厕、告警）
  ├─→ Code：获取近 7 天趋势数据
  ├─→ Code：获取近 30 天基线数据
  │
  ├─→ LLM：生成日报内容
  │    System Prompt：养老健康助手的日报生成模板
  │    User Prompt：填充当日+趋势数据
  │
  └─→ Code：推送日报
      → End
```

### Flow 3：智能问答（smart-chat）

```
Start（接收用户问题）
  │
  ├─→ Knowledge Retrieval：从养老知识库检索相关内容
  │
  ├─→ LLM：生成回答
  │    上下文：用户问题 + 检索到的知识片段
  │    安全边界："建议咨询专业医生"
  │
  └─→ End
```

## Dify API 调用参考

```bash
# 调用工作流
curl -X POST 'https://dify.example.com/v1/workflows/run' \
  -H 'Authorization: Bearer app-xxxxxx' \
  -H 'Content-Type: application/json' \
  -d '{
    "inputs": {
      "elder_id": "E001",
      "alert_level": "urgent",
      "trigger_name": "跌倒检测",
      "trigger_value": 1
    },
    "response_mode": "blocking",
    "user": "system"
  }'
```

### 响应格式

```json
{
  "data": {
    "id": "wf-run-xxx",
    "workflow_id": "wf-xxx",
    "status": "succeeded",
    "outputs": {
      "text": "紧急！老人张奶奶疑似跌倒...",
      "push_content": "{\"title\":\"跌倒告警\",\"content\":\"...\"}",
      "risk_level": "urgent"
    }
  }
}
```

## 与 FastAPI 后端服务的集成点

Dify 工作流在有 AI 增强需求时，可与以下后端服务协同工作：

### 1. wechat_service.py — 微信小程序消息推送

```
Dify 工作流 → HTTP Request 节点 → FastAPI 后端 wechat_service
```

| 集成场景 | Dify 节点 | 后端接口 | 说明 |
|---------|----------|---------|------|
| AI 生成的护理建议推送 | HTTP Request | `POST /api/v1/family/send-notification` | Dify 生成个性化护理建议，通过后端推送到家属小程序 |
| 日报 AI 润色后推送 | HTTP Request | `POST /api/v1/family/send-daily-report` | Dify 对日报进行 AI 润色后，通过后端推送给家属 |

### 2. daily_report.py — APScheduler 日报生成

```
APScheduler (每日 08:00) → 生成日报数据 → [可选] Dify 工作流 → AI 增强日报
```

| 集成场景 | Dify 节点 | 后端模块 | 说明 |
|---------|----------|---------|------|
| 日报 AI 摘要生成 | LLM 节点 | `app/services/daily_report.py` | 后端生成结构化日报数据，Dify 工作流基于数据进行 AI 分析和建议 |
| 异常趋势预警 | Knowledge Retrieval + LLM | `app/services/daily_report.py` | Dify 结合养老知识库，对连续异常数据进行趋势分析和预警建议 |

### 3. 告警处理的 AI 增强（可选）

```
FastAPI 告警产生 → [可选] 触发 Dify 工作流 → AI 生成护理建议 → 写入告警备注
```

| 集成场景 | Dify 节点 | 后端接口 | 说明 |
|---------|----------|---------|------|
| 智能护理建议 | LLM + Knowledge Retrieval | `PUT /api/v1/alerts/{id}/process` | 护理员处理告警时，可调用 Dify 获取 AI 推荐的护理措施 |
| 告警摘要 | LLM | — | 对多起告警进行智能归类和分析 |

> **设计原则**：Dify 工作流只在需要 AI 能力时被调用。所有实时性要求高的功能（跌倒告警推送、设备状态更新）由 FastAPI 后端直接处理，不经过 Dify 以避免延迟。
