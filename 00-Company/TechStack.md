```
┌─────────────────────────────────────────────────┐
│                    前端层                        │

│  React Native（移动端）                          │
│  ECharts 5（数据可视化）                         │
│  Vite 5（构建工具）                              │
└──────────────────────┬──────────────────────────┘
                       │ REST API + WebSocket
┌──────────────────────┴──────────────────────────┐
│                    后端层                        │
│  Java 17 + Spring Boot 3 + Spring Cloud          │
│  MyBatis-Plus（ORM）                             │
│  Knife4j（API 文档）                             │
│  Spring Security + JWT（认证授权）               │
│  RabbitMQ（消息队列）                            │

└──────────────────────┬──────────────────────────┘
                       │
┌──────────────────────┴──────────────────────────┐
│                    数据层                        │
│  MySQL 8.0（业务数据）                           │
│  Redis 7（缓存）                                 │
│  InfluxDB 2.x（时序数据）                        │
│  MinIO（对象存储）                               │
└──────────────────────┬──────────────────────────┘
                       │
┌──────────────────────┴──────────────────────────┐
│                  AI + 监控层                     │
│  Zabbix 6.4 LTS（监控平台）                      │
│  Dify（AI 工作流 + 知识库）                      │
│  EMQX（MQTT Broker）                             │
└──────────────────────┬──────────────────────────┘
                       │
┌──────────────────────┴──────────────────────────┐
│                  IoT 设备层                      │
│  纳米雷达 | 心率监测 | 门磁 | 水流传感器          │
└─────────────────────────────────────────────────┘
```

## 各层技术选型详解

### 前端层

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| React | 18 | 核心框架 | 生态丰富，社区活跃 |
| TypeScript | 5.x | 类型系统 | 类型安全，可维护性强 |
| Ant Design | 5.x | 组件库（管理端） | 企业级成熟方案 |
| React Native | 0.76+ | 移动端 | 复用前端技术栈 |
| ECharts | 5.x | 图表可视化 | 大屏数据展示首选 |
| Vite | 5 | 构建工具 | 开发体验好，构建快 |
| Zustand | 4.x | 状态管理 | 轻量，比 Redux 简单 |
| Less | 4.x | CSS 预处理 | 配合 Ant Design |

### 后端层

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| Java | 17 LTS | 编程语言 | 企业级稳定性 |
| Spring Boot | 3.x | 核心框架 | 生态成熟，微服务支持好 |
| MyBatis-Plus | 3.5+ | ORM | 简化 CRUD，灵活 |
| MySQL | 8.0 | 关系数据库 | 事务支持，查询灵活 |
| Redis | 7 | 缓存 | 高性能缓存与分布式锁 |
| RabbitMQ | 3.12+ | 消息队列 | 告警事件异步处理 |
| Knife4j | 4.x | API 文档 | Swagger 增强，易用 |

### 时序数据

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| InfluxDB | 2.7 | 时序数据库 | IoT 数据最佳实践 |

### AI + 监控

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| Zabbix | 6.4 LTS | 监控平台 | 企业级开源监控，稳定可靠 |
| Dify | 0.15+ | AI 平台 | 开源自部署，数据安全 |
| EMQX | 5.x | MQTT Broker | IoT 消息接入，高并发 |

### DevOps

| 技术 | 用途 |
|------|------|
| Docker | 容器化部署 |
| Docker Compose | 本地开发环境 |
| Git | 版本控制 |
| GitHub Actions / Jenkins | CI/CD（二选一） |

## 技术选型原则

1. **成熟稳定优先**：新技术固然酷，但养老系统需要稳定运行 365 天
2. **开源优先**：控制成本，Zabbix/Dify/EMQX 都是开源方案
3. **Java 生态**：团队主力技术栈，轮子多、社区好
4. **够用就好**：不引入过度复杂的方案（如 Kubernetes 在初期不需要）
